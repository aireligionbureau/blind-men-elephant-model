# 性能优化与默认激活门槛

## 目标

标准版 24 个数字人从用户提交问题到结果网页生成完毕少于 10 分钟，同时不得降低：

- 数字人完整度；
- 逐人思维阴影的具体性；
- 侦探连接质量；
- 外部来源独立性判断；
- 经典知识的权力边界；
- 真相轮廓的具体性、可追溯性和未知诚实度。

## 两条可执行链路

| 维度 | 保留基线 | 待验证优化版 |
| --- | --- | --- |
| 前半段 | `sequential` | `streaming_v2` |
| 侦探与轮廓 | `legacy_sequential` | `optimized_v2` |
| 数字人 | 24 | 24 |
| 模型、提示语义、token 上限 | 不变 | 不变 |
| 十个检测器 | 全部逐人运行 | 全部逐人运行 |
| 轮廓程序 | 候选、单路反轮廓、最终裁决 | 推测候选与三路反方草稿、最终裁决；加速材料不足时回退到裁决后三路压力 |

优化版改变调度和无损编码，不改变判断标准：

1. 每个数字人完成搜索后立即进入思考，再立即进入语义判读。
2. 人物、语义和模型请求上限为 24，搜索上限为 12。
3. 模型请求遇到限流或暂时性服务错误时自动降低并发，成功后逐步恢复。
4. 搜索源并行竞速，相同查询单飞复用，失败源熔断。
5. 内容提案和阴影提案并行；关系裁决每片最多四条、最多六片并行。
6. 轮廓材料以索引和引用去重；完整材料仍留在审计产物中。
7. 数字人材料把重复出现于候选来源、来源决定和分类列表中的同一来源合并为一份；硬校验逐项核对来源、决定、搜索意图和阴影提示后才允许调用模型。
8. 语义判读提示只提供本案真实锚点和检测器 ID，并默认只交付一个最能改写结论的根问题，减少因复制不存在的示例 ID 或罗列次要问题造成的重试。
9. 侦探层把人物坐标、来源谱系、机制集合和经典边界编码为可逆表格；调用前把表格反演回原材料逐项比对，任何缺项、篡改或悬空引用都会中止调用。
10. 内容与阴影提案完成后，侦探关系裁决和四份推测草稿同时运行。草稿只引用待审 candidate_id，明确没有事实权力；最终裁决只认裁决后 accepted 关系证书。
11. 推测草稿没有事实权力。四份中至少两份通过校验时，有效草稿仍可加速最终裁决，缺失角色由完整裁决案补读；少于两份时才回退到裁决后的证据来源、因果条件、阴影未知三路并行压力审查。无论哪条路径，最终模型都收到完整裁决案，草稿缺失不被解释为支持任何一方。
12. 每个合成子阶段记录上游输入指纹。候选变化会使反方和最终裁决缓存失效，反方变化会使最终裁决缓存失效；仅“JSON 格式仍合法”不再允许复用。
13. 优化版逐人语义判读首轮使用 `validated_fast_v1`：关闭隐藏推理，但保持完整认知链输入、输出字段和证据锁校验不变；首轮无效时自动升级为开启深思的完整重试。两种模式使用不同检查点指纹，基线结果不会被候选快路径误用。

优化版每路反方最多输出两个关键攻击和两个区分性检验，单路上限为 6144 token；三路总预算高于旧单路预算，属于职责拆分而不是削减审查。最终裁决先以完整裁决案快速生成，再由原有证据、出处、方向授权和具体性硬校验逐句审查；只有未通过时才发送紧凑修复包。改变的是调用调度，不是证明标准或正文数量限制。

## 缓存隔离

`pipeline_mode` 和 `synthesis_mode` 都写入运行清单。合成输入指纹包含 `synthesis_mode`，因此基线与优化版不能复用彼此的侦探或轮廓检查点。服务去重键也包含两种模式，同一问题的 A/B 运行不会被合并。

## 激活硬门槛

下列条件全部成立前，无参数命令和网页服务继续使用保留基线。

### 性能

- 使用标准版 24 人、真实三层信息获取和正式模型。
- 使用一个全新运行目录，不复用人物、搜索、判读或合成缓存。
- 从提交问题到 `report.html` 可用的总时间小于 600 秒。
- 运行过程中不得人工重启、修改产物或手工恢复。

### 前半段质量

- 数字人成功数为 24/24。
- 真实外部证据覆盖率不得低于基线。
- 每个人都运行十个检测器。
- 认知链评分、语义判读评分和元模型总评分不得低于基线。
- 语义回退数量不得高于基线。

### 侦探质量

- 侦探产物通过当前结构和引用校验。
- 接受关系可追溯率为 100%。
- 经典轨迹可追溯率为 100%。
- 强制关系数量为 0。
- 来源独立性必须引用实际证据谱系，数字人人数不能代替独立性。
- 独立性必须分开记录模型独立性、证据来源独立性、发布方独立性和方向性授权；不得再用一个“独立”标签掩盖未知维度。
- 顶层声称独立而证据来源仍未知，计为独立性越权，不计为独立支持。
- 关系减少不自动算退步，关系增加也不自动算进步；逐条检查其证明责任。

### 经典边界

- 经典知识充当现实证据的次数为 0。
- 经典只能辅助发现、诊断、反演授权和边界约束。
- 经典复核不得修改侦探已经冻结的材料裁决。

### 真相轮廓

- 直接答案和主轮廓都必须回答具体问题。
- 每个实质陈述都能追溯到拼图、关系或约束。
- 引用一条关系时必须引用该关系的真实端点，不得拿合法 ID 讲另一组人物或材料。
- 正文点名某个数字人时，该人物必须出现在本句引用的拼图材料中；合法关系 ID 不能替未引用的人物背书。
- 轮廓引用覆盖率为 100%。
- 无损信息包覆盖校验通过。
- 侦探无损包必须能够完整反演；三路反方材料的并集必须覆盖全部拼图、关系、约束、经典边界和未知信号。
- 定义分支、条件分支、稳定局部和重要未知不得因压缩消失。

### 跨领域对照

至少覆盖以下三类现有冻结材料：

1. AI 是否会产生意识；
2. 美股 AI 泡沫会不会很快破灭；
3. 韩国股市会不会崩盘。

每组都用优化版重新调用模型，禁止复用旧侦探和旧轮廓缓存。自动硬门槛通过后，再人工对照新旧直接答案、主轮廓、关键条件、重要未知和最强反轮廓。任一领域出现实质退步，不切默认。

## 2026-07-26 无损优化加固

- 侦探层新增可逆信息包。以韩国股市冻结材料离线测量，内容提案材料字符数减少约 36%，阴影提案减少约 35%；逐字段反演校验全部通过，任务材料删除数为 0。
- 关系裁决的小分片会自动比较完整 JSON 与索引包大小；索引包没有更小时直接发送完整 JSON，避免“为了压缩而变大”。
- 轮廓层新增三路并行反方压力审查和联合覆盖证明；任何一路分包造成拼图、关系、约束或经典边界缺口，模型调用前即失败。
- 新增安全推测执行：侦探裁决关系的同时，并行生成一个主候选草稿和三份互补反方草稿。草稿不能进入最终引用，最终裁决会先依据 candidate resolution map 删除被拒绝或未决的路线，再只用 accepted 关系重建答案。
- 推测草稿失败时自动回退到裁决后三路压力链，因而加速失败只损失时间，不会降低结果门槛。
- 新增候选、反方、最终裁决的依赖指纹与人物点名来源锁定。旧韩国股市结果不能通过新门槛，也不会被新链路误当成可复用缓存。
- 旧韩国股市前半段的 24 份语义判读共记录 41 次尝试，模型返回约 10.5 万字隐藏推理。候选链改为“先快速生成、硬校验失败再深思”，不减少任何一个人的十项检测，也不放宽证据锁；真实节时仍须由新运行证明。
- 冻结韩国股市材料的保守离线预算把合成阶段估计从 324 秒降至约 182 秒，低于内部 200 秒预算线。该数字来自旧运行时长与新提示暴露量的折算，不是真实计时证明。
- 按端到端口径，旧 cohort 72.1 秒、旧流式前半段 509.3 秒和新合成估算 182.2 秒合计仍为 763.6 秒。要进入十分钟，前半段必须降到 345.7 秒以内，即至少再减少 163.6 秒；`validated_fast_v1` 正对准旧前半段中 41 次语义尝试和约 68.9% 的隐藏推理字符，是否真正追回这段时间必须以新冷启动计时为准。
- 本轮只完成本地实现和离线校验，尚未获得新的真实运行时间与语义 A/B 证据，因此优化版仍不设为默认，也不宣称已经达到十分钟。

## 命令

普通桌面入口继续使用基线链。需要亲测候选链时显式启动另一个端口：

```powershell
.\tools\start_web.ps1 -ExecutionProfile candidate
```

`/api/health` 会返回 `execution_profile`、`pipeline_mode` 和
`synthesis_mode`。启动脚本只复用模式和运行命名空间完全相同的本地服务，避免
把已运行的基线服务误认成候选链。候选网页写入独立的 `runs-candidate`，因此历史
基线、旧题缓存和待恢复任务不会污染冷启动计时；候选目录自身仍保留断点恢复。

优化版完整运行：

```powershell
$env:PYTHONPATH="src"
python -m bme_model run-standard-live "韩国股市会不会崩盘" `
  --provider three-layer `
  --pipeline-mode streaming_v2 `
  --synthesis-mode optimized_v2 `
  --concurrency 24 `
  --retrieval-concurrency 12 `
  --semantic-concurrency 24 `
  --model-concurrency 24 `
  --output-dir runs
```

冻结材料的跨领域优化版重算：

```powershell
python tools/audit_pipeline_upgrade.py live-synthesis `
  runs/20260724-191147-280353-standard-958612 `
  runs/20260725-115057-504851-standard-509a49 `
  runs/20260725-232307-673115-standard-f36969
```

完整运行的新旧硬门槛比较：

```powershell
python tools/audit_pipeline_upgrade.py compare runs/BASELINE_RUN runs/OPTIMIZED_RUN
```

三领域激活总门：

```powershell
python tools/audit_pipeline_upgrade.py suite benchmarks/cross-domain-acceptance.json
```

总门把质量拆成数字人完整度、阴影具体性、连接质量、来源独立性、经典边界和
真相轮廓质量六组。机器门槛全部通过后，仍需对隐藏版本顺序的结果进行逐项内容
复核并留下理由；缺少候选运行或内容复核时，`default_switch_allowed` 必须保持
`false`。

候选冷启动预检不会发出任何外部请求：

```powershell
python tools/run_activation_candidate.py korea-stock-crash
```

得到具体问题的明确外发授权后，才添加执行开关：

```powershell
python tools/run_activation_candidate.py korea-stock-crash `
  --authorize-external-calls
```

该命令固定使用 24 人、`streaming_v2 + optimized_v2` 和独立的
`runs-candidate`，成功后自动写入实测时间、候选运行目录、A/B 盲序复核包与三领域
